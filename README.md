# مِداد | Medad — Commerce Partnership OS

مِداد مساحة عربية لإدارة الشراكة التجارية: اكتشاف مرشحي المنتجات، جمع الأدلة، حساب اقتصاديات الطلبات المسلّمة والمرتجعات، اختبار السيناريوهات، إعداد عروض الشراكة، وبناء تدفق أحداث واضح باسم Instant ⚡.

## الحالة الحالية

- واجهة عربية متجاوبة تعمل محليًا من `index.html`.
- محرك اقتصاديات الوحدة في `engine/engine.py`، وتحليل الحساسية في `engine/sensitivity.py`.
- نواة الأدلة والادعاءات والبوابات في `engine/decision_kernel.py`، وبوابات المنتج المتخصصة في `engine/opportunity.py`.
- مجمّع التشغيل `engine/workflow.py`: ينتج حزمة قرار واحدة تربط الاقتصاديات والادعاءات والبوابات والحساسية وInstant مع تجزئة المدخلات والتقرير، دون تنفيذ إجراءات خارجية.
- سجل حزم القرار `engine/run_journal.py`: سجل JSONL اختياري محلي، idempotent مع كشف تغيّر السجل غير المقصود عبر checksum؛ ليس مخزنًا إنتاجيًا أو مقاومًا للعبث.
- محرك Instant وقواعد التنبيه وسجل JSONL محلي idempotent في `engine/instant.py`.
- المنهج التشغيلي الدائم في `docs/OPERATING_METHOD.md`، مع تعريف النموذج وحدود البيانات في `docs/PRODUCT_MODEL.md` و`docs/MARKET_RESEARCH.md`.
- اختبارات تلقائية تغطي المحركات والتحقق من الواجهة عبر GitHub Actions.

**لا توجد حتى الآن اتصالات حيّة بالمنتجات أو الموردين أو شركات التوصيل أو أنظمة الإعلان أو الطلبات أو الشركاء، ولا نموذج ذكاء اصطناعي متصل.** يحتوي مختبر المنتجات على لقطات أسعار معروضة من صفحات عامة راجعناها بتاريخ محدد؛ هذه ليست أسعار صفقات أو عروض جملة، ولا تثبت الطلب أو الربحية.

## تجربة الواجهة

افتح `index.html` في متصفح. تحتوي على: نظرة عامة، Instant ⚡، مختبر المنتجات، حاسبة اقتصاديات الوحدة، عروض الشراكة، وصفحات تحضيرية للشركاء والطلبات.

## تشغيل المحرك والاختبارات

يتطلب Python 3.10+ دون حزم خارجية:

    cd engine
    python -m unittest -v
    python engine.py
    python opportunity.py

## ما يحسبه المحرك

- الطلبات المسجلة والمتوقّع تسليمها والمرتجعة والمحتفظ بها.
- الإيراد وتكلفة المنتجات والتغليف والشحن الخارجي وتكلفة رفض/عودة الطلب والمرتجعات.
- قيمة مخزون المرتجعات غير القابلة للاسترداد، بدل إسقاط تكلفة كل مرتجع تلقائيًا.
- ميزانية الإعلانات، ربح النموذج، الهامش، CAC لكل طلب مسجل ولكل طلب محتفظ به، وحد إنفاق التعادل.
- سيناريوهات ضغط وأساسي وتحسن، ومؤشر إرشادي لجودة الأدلة.

مؤشر جودة البيانات **ليس احتمال ربح**. السيناريوهات صدمات حتمية توضيحية وليست توقعات احتمالية معايرة. النموذج يحتاج تكييفًا مع شروط شركة التوصيل الفعلية: متى يتم احتساب الشحن، ومن يدفع رسم التوصيل، وكيف تُعالَج الإلغاءات قبل الإرسال.

## منهج التشغيل والمحركات

- **RIV**: بحث → تنفيذ → تحقق، ثم قرار وإعادة تحقق عند تغير الأدلة.
- **Claim/Evidence Kernel**: يحفظ تصنيفات ESTABLISHED وEXPERIMENTALLY_SUPPORTED وUSER_REPORTED وINFERENCE وHYPOTHESIS وCONTRADICTED وUNKNOWN وOPEN؛ ولا يرفع الفرضية آليًا إلى حقيقة.
- **Decision Gates**: PASS فقط مع مرجع دليل صريح؛ UNKNOWN وFAIL يمنعان الانتقال.
- **Sensitivity Engine**: تغييرات أحادية العامل وحدود تعادل داخل نطاق محدد؛ لا تنتج احتمالات أو تحسن درجة الأدلة.
- **Decision Workflow**: `python cli.py workflow --input decision-run.json` ينتج حزمة تحليل تربط المحركات. يتطلب المدخلات الجوهرية وإصدار الشفرة صراحةً، ويمنع الانتقال عند نقص الأدلة أو البوابات أو الادعاءات الحرجة؛ لا يمنح إذنًا بالإنفاق.
- **Run Journal**: يمكن اختيار `--run-journal .medad/decision-runs.jsonl` لحفظ حزم القرار محليًا مع منع تكرار معرّف التشغيل بمدخلات مختلفة. لا يكتب سجل التشغيل ما لم يُطلب الخيار صراحةً.
- **Instant**: زر «افحص لقطة الحاسبة» يولّد تنبيهات محلية من المدخلات، مع الإقرار والحل وإعادة الفتح وتصدير JSON. السجل في المتصفح مؤقت للجلسة فقط؛ سجل Python في JSONL محلي لا يتزامن معه.
- **حدود حالية**: لا توجد قاعدة بيانات أو صلاحيات متعددة المستخدمين أو مزامنة أحداث أو تكامل حي مع الموردين/التوصيل/الإعلانات، ولا نشر إنتاجي. يجب عدم وصف أحداث Instant الحالية بأنها تغيّرات سوق حية.

## أدلة المنتج

كل إدخال مهم ينبغي أن يحمل المصدر وتاريخ الملاحظة والجغرافيا والعينة والعملة وتصنيفًا:
- `observed`: قياس فعلي من الطلبات أو الحملات.
- `quoted`: عرض سعر موثق وحديث.
- `estimated`: تقدير معلن المنهج.
- `assumed`: افتراض غير مثبت.

لا ترتّب المنتجات باعتبارها «رابحة» اعتمادًا على بيانات مصطنعة. اجمع أدلة المورد والسعر والجودة والطلب وتكلفة الإعلان والتسليم قبل أي التزام مخزون.

## البحث السوقي الحالي

- لقطات البحث المؤرخة في `data/research_snapshot_2026-10-29.json` تسجل أربع مرشحات ومصادرها وحدود كل مصدر، إضافة إلى خمسة مسارات لاكتشاف الموردين/طلب سعر الجملة (كلها غير متحققة).
- شرح المنهج والمصادر في `docs/MARKET_RESEARCH.md`.
- جميع المرشحات الحالية بحالة `RESEARCH_ONLY`: لا يوجد عرضان من الموردين، ولا تكلفة وصول، ولا تعرفة توصيل خاصة بالتاجر، ولا بيانات حملة وطلبات مسلّمة/مرتجعة متصالحة. البحث الإضافي عن منافسين خفّض الثقة في فرضية منظّم مقعد السيارة بسبب بدائل أرخص أو غير قابلة لإعادة التحقق؛ لا نعدّها مقارنات SKU مؤكدة.
- مسارات الموردين الحالية تشمل Hnaya Source وKabagros وItidjar وإعلان SVC/خيار Shoppicom؛ هذه مسارات بحث/تواصل فقط وليست عروض أسعار. لم يُشترَ أي اشتراك ولم يتم التحقق من أي تاجر أو التواصل معه نيابةً عن المستخدم.
- محرك بوابات الجاهزية في `engine/opportunity.py` لا يحسب «درجة ربحية» مصطنعة؛ لا يسمح بالانتقال إلى مرحلة ما قبل الاختبار قبل توثيق عينة المنتج، عروض الموردين، التكلفة الكاملة وشروط شركة التوصيل.
- تم تصحيح نقطة التعادل: إذا كانت المساهمة قبل الإعلانات لا تغطي التكاليف الثابتة، يُعرض أن التعادل غير ممكن قبل خفض التكاليف/تغيير العرض؛ لا تُعرض ميزانية تعادل زائفة تساوي صفرًا.

## شراكة العمل

- الشريك: التمويل وشراء المخزون والتخزين وتجهيز الطلبيات والتنسيق مع شركة التوصيل.
- مِداد: البحث عن المنتجات، وإعداد العرض والتسويق والإعلانات وجلب الطلبيات ومراقبة النتائج.
- قبل التشغيل يجب الاتفاق كتابيًا على تعريف صافي الربح، وملكية المخزون، والخسائر والمرتجعات، وسقف ميزانية الإعلان، والموافقات والتسوية والخروج من الشراكة. لا يفرض المحرك نسبة تقاسم.

## خارطة التنفيذ

1. ربط البحث بمصادر منتجات وأسعار وأدلة يمكن مراجعتها.
2. إضافة مصادر الموردين والتوصيل والطلبات والحملات مع سجل مصدر وتاريخ لكل معلومة.
3. بناء تخزين وصلاحيات وسجل أحداث حقيقي، ثم ربط تنبيهات Instant بتغيّرات فعلية.
4. تحويل النتائج إلى عروض شراكة قابلة للمراجعة والتفاوض، دون وعود أرباح مضمونة.
5. تنفيذ اختبارات تكامل وتدفق مستخدم ونشر قبل اعتبار النظام جاهزًا للإنتاج.
